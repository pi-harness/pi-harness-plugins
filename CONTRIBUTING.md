# Contributing

Open an issue before large changes. Keep changes focused, document user-visible behavior, and run the repository validation command before opening a pull request.

## Pull request checklist

- [ ] The plugin has a unique `@pi-harness/plugin-*` name.
- [ ] Runtime dependencies are declared in that package manifest.
- [ ] README documents configuration, permissions, and compatibility.
- [ ] `npm run validate` passes locally.
- [ ] Version and changelog entries are updated when behavior changes.
